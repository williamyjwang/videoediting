# MCC cloud editing

The intended user workflow is a private HTTPS website: sign in, upload footage, start an edit/render, close the browser, and return to **Saved projects** for the result. No software needs to be installed on the user's device. Let an upload finish before closing the browser; uploading a file still requires a connected device.

## Prepared deployment

`Dockerfile` installs Node 24, FFmpeg, Chromium, and the pinned Codex CLI. `render.yaml` defines a single paid, always-on Render web service with a 20 GB persistent disk. Render supplies HTTPS. Review its current service and storage prices before creating the service; this file does not provision or purchase hosting.

The deployment is **not live yet**. Use `williamyjwang/videoediting` as the Render source repository. The repository includes the application, original logos, Dockerfile, and deployment blueprint. Hosting credentials must be entered securely in Render; a successful source upload does not establish that a service has deployed.

## Account-owner steps

1. Create a Render account at https://render.com, ideally using the GitHub account that owns `williamyjwang/videoediting`.
2. Make the completed source available in that repository, then authorize Render for that repository.
3. Create a **Blueprint** from the repository. Render reads `render.yaml` and displays the proposed service/disk for review. Use one instance; this version uses an attached disk and a single worker.
4. Enter `MCC_ADMIN_PASSWORD` as a unique passphrase of at least 16 characters and `MCC_OPENAI_API_KEY` securely in Render's environment-variable settings. `MCC_SESSION_SECRET` is generated by the blueprint. Do not send these values in chat, commit them, or put them in the build settings.
5. Review hosting costs and create the service. Wait for a successful build and health check, then open the HTTPS address Render assigns. This cloud provider deployment is separate from publishing the Codex development environment.
6. Sign in, try the synthetic sample, render it, close the browser, and return through **Saved projects**. Then test a short real spoken video to verify live transcription and planning. Missing AI credentials should still allow sample/manual rendering.

The first setup needs account ownership and secure secret entry. After deployment, editing runs on the hosted server; the user's computer is not the render worker.

## Runtime

- `NODE_ENV=production` refuses to start without a 16+ character admin password and a 32+ character session-signing secret.
- Sign-in uses a signed HttpOnly, SameSite=Strict cookie, marked Secure in production. Login attempts are rate-limited. API operations, footage, and MP4 downloads require sign-in. The health endpoint and app's static assets are public.
- This is a single-owner private studio with a shared studio password, not a multi-tenant service. All signed-in users share the same projects. Rotate the session secret to revoke all existing sessions.
- `/var/data` contains source media, exports, project JSON, temporary files, and the SQLite job queue. Keep the disk attached across restarts/deployments. Deleting or replacing it loses these files. Arrange and test off-service backups before relying on it for irreplaceable footage; the app does not provide off-site backups.
- Jobs are stored before the API returns acceptance. A server worker processes them serially without a browser connection. Queued jobs persist; an interrupted running job is retried once after restart. A second interruption marks it failed for an explicit retry. A retried AI request may incur another API charge.
- This version must remain at one instance. For multiple workers, migrate the queue to a shared database and files to object storage before scaling.
- The sample render can use substantial CPU; the blueprint starts with a paid standard service and one render thread. Increase resources if real footage exceeds memory limits. Free/sleeping services and request-only serverless functions do not fit this worker/storage design.
- Codex planning uses `codex exec` with `CODEX_API_KEY` supplied only in the child process from the server-side `MCC_OPENAI_API_KEY` binding. No interactive CLI login is needed when that API binding works and the account has model access. Actual model access remains unverified without a key. `MCC_EDIT_PROVIDER=openai` uses the direct Responses API instead.
- Render's ingress upload limits still apply. The application's 2 GB limit is a maximum, not a guarantee of provider acceptance. Validate representative upload sizes on the real host before relying on it for long footage; resumable/direct-to-object-storage uploads are a later extension.

## Validation

`npm test` covers cut logic, session signatures, durable queue recovery, duplicate-job prevention, and completed-job behavior. `npm run test:cloud` starts an isolated password-protected API, rejects unauthenticated media/downloads, signs in through Chromium, queues a real Remotion render, closes the browser, restarts the API against the same disk, and verifies a fresh browser can find/download the output.

## Latest pilot validation (2026-10-20)

The current source adds editable English/Chinese captions, source-timed SRT import and cut-timed SRT export, subtitle coverage/readability checks, undo/redo, per-project editing feedback, and vertical (9:16), horizontal (16:9), and portrait (3:4) output presets. All output presets support up to 20 minutes. New uploads start with the complete source timeline; aspect ratio does not determine duration. Media remains on the existing disk and jobs use the existing single worker.

The default **Subtitles only** approach preserves the entire video. **Light trim** is optional and has no target length: the planner is asked to retain the complete explanation and remove only obvious dead air, false starts or redundant repetitions. A proposed edit retaining less than 80% of source runtime or 90% of transcript words falls back to the full source with a visible notice. It does not apply automatic pause tightening afterward. Legacy target-duration fields are ignored. The former `MCC_AI_MAX_SOURCE_SECONDS` pilot restriction is removed and ignored; source footage remains limited to 20 minutes / 2 GB.

Automatic captions handle English/Chinese language switches. `MCC_TRANSLATION_MODEL` defaults to `gpt-4.1-mini`. Translation and a separate automatic review pass both receive the whole source transcript, working in batches of up to 40 cues to bound response size. Instructions request natural North American English and mainland Chinese phrasing, idiomatic cultural meaning, consistent terminology, and no invented context or claims. Returned IDs, both language fields, and source timestamps are validated. Existing corrected language text is preserved; missing language fields are completed. Successful transcription is checkpointed before planning/translation so a later failed stage need not retranscribe audio. Retrying an unfinished translation can still incur additional usage. Automatic review is not proof of semantic accuracy against the audio.

Caption-only bypasses Codex/planning entirely. Light trimming uses the configured planner. Project feedback influences the next light trim; it does not train a model or create a global reference library. API usage can incur charges for the full audio duration and translation/review passes.

To test the container after a successful image build, supply secrets at runtime rather than in the image, mount a persistent volume at `/var/data`, and check `/api/health`. Verify sign-in through an HTTPS proxy so the Secure session cookie can be used. A container build, current-instance smoke check, or Codex environment publication is not evidence that Render has deployed the service.

The image preserves HTTPS and package-signature/integrity checks. Its optional BuildKit secret `build_ca` supports a trusted development-network CA bundle during installation; it is not copied into the resulting image. Normal cloud builds use Node's bundled public CA roots to bootstrap apt's HTTPS trust, then install the OS certificate package. Never disable certificate or package verification to work around a proxy.
